### Claude Code 跨会话消息与模型配置更新 (v2.1.236)

- **发生了什么**：Claude Code v2.1.236 引入 `ANTHROPIC_DEFAULT_MODEL` 环境变量以设置新会话默认模型，并为跨会话 `SendMessage` 添加了 `notify_when_idle` 选项。
- **背景**：在多会话或跨工具协作的 Agent 工作流中，默认模型的配置和会话间通信的响应性是重要的工程考量。
- **证据**：根据 GitHub Release 页面（tag: v2.1.236），更新添加了 `ANTHROPIC_DEFAULT_MODEL` 环境变量（与现有 `ANTHROPIC_MODEL` 行为不同，不被 `/model` 持久化覆盖），并在跨会话 `SendMessage` 中增加了 `notify_when_idle` 选项，允许一个会话请求另一个会话在空闲时通知。
- **分析**：`notify_when_idle` 是构建健壮的多 Agent 系统的一个微小但关键的步骤，它使 Agent 之间的通信从“发送即忘”变为“可等待响应”，增强了流程的可靠性和可观测性。环境变量的改进则提供了更清晰的配置分层。
- **影响**：虽然用户当前主要使用 Mimo 模型后端，但 Claude Code 作为主流 Agent 客户端的工作流设计方向值得借鉴。`notify_when_idle` 的思路可以启发用户在设计自己的诊断或自动化工具时，如何更好地处理异步任务的结果回调与状态同步。
- **建议行动**：无需立即行动。建议持续关注 Claude Code 在 Agent 工作流编排方面的后续发展，特别是如何利用这些原语构建复杂的、有状态的任务流程。
- **局限**：这些功能深度集成于 Claude 生态，其 API 和设计模式是否完全通用或可迁移到其他模型后端需要评估。
- **状态**：已确认

### OpenAI 为前沿模型提供零数据保留选项

- **发生了什么**：OpenAI 宣布为其前沿模型提供“零数据保留”选项。
- **背景**：大型语言模型服务商通常会保留用户输入数据用于模型改进或安全监控，这对于涉及知识产权或敏感信息的项目构成潜在风险。
- **证据**：OpenAI 官方博客文章《Offering Zero Data Retention For Frontier Models》宣布了此政策变化，为特定的前沿模型提供数据不被保留的选项。
- **分析**：此举反映了模型提供商在数据隐私方面的政策分化。对于需要处理公司内部代码、诊断日志或个人敏感数据的开发者而言，数据保留政策是选择模型服务的关键考量之一。零数据保留是降低合规风险与数据泄露可能性的重要保障。
- **影响**：即使用户当前使用 Mimo API，此项政策也定义了模型服务市场的一个重要安全基线。用户在未来构建任何涉及敏感数据的 AI 工具或进行模型后端调研时，都应将“数据保留政策”作为核心评估项。这与用户关注的“重大安全与可靠性风险”直接相关。
- **建议行动**：建议将“数据保留政策”纳入未来评估任何第三方模型 API 时的标准清单。在涉及敏感数据的个人项目中，优先选择提供明确数据隔离或零保留选项的服务。
- **局限**：“零数据保留”的具体技术实现、审计方式以及适用的模型范围需要进一步查证。可能存在使用条件或限制。
